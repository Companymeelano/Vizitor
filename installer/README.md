# نصب‌کنندهٔ ویندوز ویزیتور — `Vizitor-Setup.exe`

فایل نصب تک‌فایلی سامانهٔ ویزیتور برای **ویندوز ۷ / ۸ / ۸.۱ / ۱۰ / ۱۱**
(۳۲ و ۶۴ بیتی) با رابط فارسی راست‌به‌چپ، آیکن اختصاصی، **انتخاب بخش‌ها با
تیک** و **کد فعال‌سازی**.

| | |
|---|---|
| نام فایل | `release/Vizitor-Setup-1.0.0.exe` |
| حجم | 679٬238 بایت (≈ 663 کیلوبایت) |
| بررسی سلامت | `certutil -hashfile Vizitor-Setup-1.0.0.exe SHA256` (هش در هر ساخت دوباره تغییر می‌کند) |
| موتور | NSIS 3.03 (Unicode) — MUI2 |
| نیازمند | دسترسی Administrator (خود نصب‌کننده درخواست می‌کند) |
| فایل‌های همراه | `install.ps1`، `api/*.py`، `database/*.sql`، بستهٔ فارسی مهاجرت (`android-sql-direct`)، مولد QR (segno، مجوز BSD-3) |

> ⚠ این فایل داخل سندباکس لینوکس ساخته شده است. ساخت و بسته‌بندی و امضای
> فایل‌ها درست است، اما **اجرای واقعی آن روی ویندوز را باید یک‌بار خودتان
> تست کنید**؛ بخش «چک‌لیست تست» پایین همین فایل را ببینید.

## ۱) بخش‌هایی که تیک می‌خورند (صفحهٔ Components)

| # | بخش | پیش‌فرض | کار آن |
|---|------|---------|--------|
| ۱ | **هستهٔ سامانه — API و سرویس (اجباری)** | ✅ (قفل) | فایل‌های API، سرویس ویندوز `VizitorAPI`، ابزارها، پیکربندی |
| ۲ | پیش‌نیازهای پایتون (pyodbc و درایور ODBC) | ✅ | نصب خودکار pyodbc و درایور ODBC (فقط اگر کم باشد) |
| ۳ | دیتابیس سامانه در SQL Server | ✅ | ساخت دیتابیس/جداول داخلی ویزیتور — کاملاً غیرتلفیقی |
| ۴ | قاعدهٔ فایروال ویندوز | ✅ | پورت **۱۴۳۳** فقط برای شبکهٔ محلی (اتصال اپ) + پورت پنل ۹۵۹۵ |
| ۵ | اتصال مستقیم اندروید به SQL Server | ✅ | کاربر محدود `vizitor_android` + گرنت‌های تأییدشده + کارت اتصال/QR + بررسی سلامت |
| ۷ | راهنماها و اسکریپت‌های SQL (بستهٔ فارسی) | ✅ | کپی راهنماها، گزارش نهایی مهاجرت و اسکریپت‌های بازرسی در `docs` |
| ۸ | میان‌بر دسکتاپ و منوی استارت | ✅ | پنل مدیریت، بازرسی و تعمیر، شروع/توقف سرویس، حذف نصب |
| ۹ | بازرسی و تعمیر خودکار پس از نصب | ✅ | چک‌کردن API/دیتابیس/فعال‌سازی/لاگین و تعمیر خودکار (تا ۴ دور) |

هر بخشی را تیک نزنید، همان مرحله در `install.ps1` با سوئیچ متناظر
(`-SkipDatabase`، `-SkipFirewall`، `-SkipPrerequisites`،
`-SkipAndroidPrep`، `-SkipSelfCheck`) رد می‌شود.

## ۲) صفحه‌های نصب‌کننده

1. **خوش‌آمد** — معرفی و تصویر اختصاصی ویزیتور
2. **شرایط استفاده** — متن فارسی
3. **انتخاب بخش‌ها** — همان جدول بالا (تیک‌ها + توضیح هر بخش)
4. **پوشهٔ نصب** — پیش‌فرض `C:\Vizitor`
5. **تنظیمات سرور و دیتابیس** — آدرس/IP سرور (خودکار از شبکه تشخیص داده
   می‌شود)، پورت پنل، سرور/پورت/کاربر/رمز SQL Server (رمز با
   `***` نمایش داده می‌شود)، نام دیتابیس سامانه، نام دیتابیس ERP (پیش‌فرض
   `Meelano`) و **پیش‌نمایش زندهٔ آدرس نهایی API**
6. **کد فعال‌سازی** — کد را وارد کنید یا تیک «فعلاً کد ندارم» را بزنید
7. **نصب** — لاگ زندهٔ همهٔ کارها (همان خروجی فارسی `install.ps1`)
8. **پایان** — آدرس API، میان‌بر بازکردن پنل، نمایش `connect.txt`، لینک پوشهٔ راهنما

## ۳) پشت صحنه (چطور به هم وصل می‌شوند)

```
Vizitor-Setup.exe (NSIS)
   ├─ preflight.ps1  →  ip / python / sql / admin / ps  را تشخیص می‌دهد
   ├─ پاسخ صفحه‌ها   →  %TEMP%\<plugins>\answers.ini  (INI ساده، بدون مشکل escape)
   └─ install.ps1 -Answers answers.ini -AppHome <پوشه> [-Skip…ها]
            ├─ پیش‌نیازها، انتشار فایل‌ها، config.json
            ├─ قاعدهٔ فایروال (۱۴۳۳ شبکهٔ محلی + پورت پنل)
            ├─ provision_sqlserver.py  (جداول سامانه، غیرتلفیقی)
            ├─ provision_android_sql.py (کاربر vizitor_android + گرنت‌ها)
            ├─ سرویس VizitorAPI + بازرسی/تعمیر تا ۴ دور
            └─ connect.txt  (آدرس API و مشخصات، بدون رمز)
```

`install.ps1` همان نصب‌کنندهٔ هوشمند قبلی است و بدون هیچ پارامتری هنوز
دقیقاً مثل قبل و کاملاً پرسشی کار می‌کند؛ پارامترهای جدید فقط برای زمانی
است که نصب‌کنندهٔ گرافیکی آن را صدا می‌زند.

## ۴) امنیت

* **رمز SQL Server هیچ‌جا نمایش داده نمی‌شود**: در صفحهٔ مخصوص با `***`
  گرفته می‌شود، در `answers.ini` موقت است، بعد از نصب همان فایل پاک
  می‌شود و در لاگ‌ها/گزارش‌ها/خطاها چاپ نمی‌شود.
* رمز اتصال مستقیم اندروید به‌صورت خودکار ساخته می‌شود و فقط در
  `C:\ProgramData\Vizitor\android_app_password.txt` با ACL محدود
  (SYSTEM + Administrators) ذخیره می‌شود؛ فقط مسیر فایل چاپ می‌شود.
* پوشهٔ `C:\ProgramData\Vizitor` (که `config.json` و رمز دیتابیس در آن است)
  در پایان نصب ACL محدود می‌گیرد.
* قاعدهٔ فایروال پورت ۱۴۳۳ فقط برای `LocalSubnet` باز می‌شود (نه اینترنت).
* رفتار دیتابیس **غیرتلفیقی** است: فقط `CREATE … IF NOT EXISTS`؛ هیچ
  `DROP`/`TRUNCATE`/`ALTER` روی اشیای موجود، و هیچ تغییری در تنظیمات سرور.

## ۵) مسیرهای نصب

```
C:\Vizitor\                ← پوشهٔ نصب (AppHome؛ قابل تغییر در ویزارد)
├─ setup\                  ← بستهٔ اصلی: install.ps1، api\، database\، preflight.ps1، connect.txt
├─ tools\                  ← میان‌برهای bat: بازرسی، شروع/توقف سرویس، پنل، اتصال مستقیم SQL
├─ docs\                    ← راهنماهای فارسی + docs\migration (کل بستهٔ android-sql-direct)
├─ api\ run.bat            ← سرویس و پنل سامانه (توسط install.ps1)
└─ uninstall.exe
C:\ProgramData\Vizitor\    ← config.json، vizitor.log، vizitor.pid، android_app_password.txt
```

## ۶) حذف نصب

`uninstall.exe` (یا «برنامه‌ها و ویژگی‌ها») این کارها را می‌کند:
توقف و حذف سرویس `VizitorAPI`، حذف قاعده‌های فایروال `Vizitor API` و
`Vizitor SQL 1433`، حذف میان‌برها و فایل‌های برنامه (IIS در نصب جدید استفاده نمی‌شود؛
فقط اگر از نسخه‌های قبلی سایتی با نام `VizitorAPI` مانده باشد، پاک می‌شود).
از شما می‌پرسد که `C:\ProgramData\Vizitor` هم پاک شود یا نه — و
**داده‌های دیتابیس در هر حالت دست‌نخورده می‌مانند** (هیچ جدولی حذف نمی‌شود).

## ۷) ساخت دوبارهٔ فایل نصب

**روی ویندوز:**
```
1. NSIS 3 را نصب کنید:  https://nsis.sourceforge.io/Download
2. در ریشهٔ مخزن اجرا کنید:   installer\build.bat
3. خروجی:  release\Vizitor-Setup-1.0.0.exe
```

**روی لینوکس/CI:**
```
sudo apt install nsis        # یا NSISDIR=/opt/nsis
./installer/build.sh
```

آیکن و تصاویر ویزارد از `installer/assets/` می‌آیند و با
`python3 installer/assets/make_branding.py` بازتولید می‌شوند
(`vizitor.ico` چند-اندازه: ۱۶ تا ۲۵۶ پیکسل).

## ۸) نصب بی‌صدا (اختیاری، برای مدیر سیستم)

```
Vizitor-Setup-1.0.0.exe /S
```
در حالت بی‌صدا همهٔ صفحه‌ها رد می‌شوند و `install.ps1` با مقادیر پیش‌فرض
(IP شناسایی‌شده، `localhost`/`1433`، کاربر `sa`، دیتابیس `vizitor`) اجرا
می‌شود. اگر حساب `sa` رمز داشته باشد، این حالت مناسب نیست — از حالت
گرافیکی استفاده کنید.

## ۹) چک‌لیست تست (لطفاً یک‌بار روی سرور انجام دهید)

- [ ] فایل روی ویندوز ۷ و ویندوز ۱۰/۱۱ اجرا می‌شود و UAC می‌پرسد.
- [ ] آیکن فایل و آیکن نصب‌شده، آیکن ویزیتور است.
- [ ] متن‌های فارسی درست و راست‌به‌چپ دیده می‌شوند (بدون علامت سؤال).
- [ ] آدرس IP سرور در صفحهٔ تنظیمات خودکار پر شده است.
- [ ] صفحهٔ بخش‌ها تیک‌ها را نشان می‌دهد و می‌شود خاموش/روشن کرد.
- [ ] کد فعال‌سازی ثبت می‌شود (یا «بعداً» کار می‌کند).
- [ ] در پایان: «همه بازرسی‌ها پاس شد» سبز است و آدرس API نشان داده می‌شود.
- [ ] صفحهٔ وب `http://<IP>:<port>/api/health` در مرورگر جواب می‌دهد.
- [ ] میان‌بر «بازرسی و تعمیر» کار می‌کند.
- [ ] حذف نصب، سرویس و قاعده‌های فایروال را پاک می‌کند و دادهٔ دیتابیس را
      دست نمی‌زند.
- [ ] اگر بخش «اتصال مستقیم اندروید» تیک خورده باشد: کاربر
      `vizitor_android` در SQL Server ساخته شده، پورت ۱۴۳۳ فقط برای
      شبکهٔ محلی باز است و فایل رمز با دسترسی محدود وجود دارد.

اگر جایی خطا دید، خروجی کامل پنجرهٔ لاگ نصب را بفرستید — همان متن،
دقیقاً همان چیزی است که برای رفع مشکل لازم است.

## ۱۱) اتصال اندروید در یک قدم: کارت اتصال و کد QR

پس از نصب (اگر بخش «اتصال مستقیم اندروید» تیک خورده باشد) این فایل‌ها ساخته می‌شوند:

```
C:\Vizitor\setup\android-connect.png     ← کد QR ؛ با برنامه اسکن کنید
C:\Vizitor\setup\android-connect.txt     ← کارت متنی فارسی (سرور، دیتابیس، کاربر، کد راه‌اندازی)
C:\Vizitor\setup\android-connect.json    ← همان اطلاعات برای برنامه‌نویس اندروید (بدون رمز)
C:\ProgramData\Vizitor\android_config.json  ← نسخهٔ کامل با رمز (دسترسی: فقط SYSTEM و Administrators)
```

**ویزیتور هیچ چیزی تنظیم نمی‌کند:** QR را یک‌بار با برنامه اسکن می‌کند (یا فقط نشانی سرور را
می‌زند) و بعد فقط **نام کاربری و کلمهٔ عبور خودش** را وارد می‌کند.

محتوای QR:

```
vizitor://c?h=<سرور>&p=1433&d=<دیتابیس ERP>&u=vizitor_android&t=<کد راه‌اندازی>&a=<آدرس API>
```

**سمت سرور (همین حالا کار می‌کند و تست شده):**

| درخواست | پاسخ |
|---|---|
| `GET http://سرور/api/config` | `direct_sql` بدون رمز: سرور، پورت، دیتابیس، کاربر، `token_required` |
| `GET http://سرور/api/direct-sql/setup` با هدر `X-Vizitor-Token: <کد>` | همان + `password` و `connection_string` آمادهٔ JDBC |
| همان بدون کد یا با کد غلط | `403 bad_setup_code` (و ۱۰ تلاش غلط = یک دقیقه قفل) |

* کد راه‌اندازی در نصب ساخته می‌شود، در QR و کارت متنی است و **در لاگ‌ها ستاره‌دار (`***`) می‌شود**.
* اگر می‌خواهید بدون کد باشد (فقط شبکهٔ محلی و به‌خواست خودتان): در
  `C:\ProgramData\Vizitor\config.json` داخل `direct_sql` مقدار `"setup_token": ""` بگذارید و
  `"allow_anonymous": true` را ست کنید. **پیش‌فرض امن است.**
* اگر نشانی سرور یا کد عوض شد، میان‌بر «اتصال مستقیم SQL» را یک‌بار اجرا کنید: QR و کارت دوباره ساخته می‌شوند.

## ۱۲) جایگزینی نصب قبلی — دقیقاً چه چیزی پاک می‌شود

اگر نصب قبلی پیدا شود، در همان ابتدا می‌پرسد:

| انتخاب | نتیجه |
|---|---|
| **بله** = بازرسی و تعمیر | هیچ فایلی پاک نمی‌شود؛ فقط همه‌چیز بررسی و در صورت نیاز تعمیر می‌شود |
| **خیر** = پیکربندی دوباره | فایل‌های *برنامه* جایگزین می‌شوند: `setup`، `api`، `docs`، `tools`، `run.bat` (اول سرویس متوقف می‌شود) |
| **انصراف** | نصب انجام نمی‌شود |

در هر حالت این‌ها **دست‌نخورده** می‌مانند:

* `C:\ProgramData\Vizitor` → `config.json`، لاگ‌ها، `vizitor.db` (اگر sqlite)، فایل رمز، کارت‌های اتصال.
  (اگر پاک کردنش را بخواهید، فقط در «حذف نصب» و با پرسش صریح انجام می‌شود.)
* **دیتابیس SQL Server** → هیچ جدول/داده/شیئی پاک یا بازنویسی نمی‌شود (بخش بعدی).

## ۱۳) «بدون هیچ تغییر در دیتابیس» یعنی چه؟

| کار | تغییر در ERP؟ |
|---|---|
| بررسی دسترسی و نسخهٔ SQL Server | فقط خواندن |
| ساخت دیتابیس/جداول خود سامانهٔ ویزیتور (`provision_sqlserver.py`) | فقط `CREATE` برای چیزهایی که **نیستند**؛ هیچ `DROP`/`ALTER`/`TRUNCATE` |
| کاربر اتصال اندروید (`provision_android_sql.py`) | ساخت **لاگین/یوزر** و `GRANT` (فقط اگر نباشد؛ رمز لاگین موجود هرگز عوض نمی‌شود) |
| جدول‌های ERP (Meelano) | **هیچ تغییری** — نه ساخت، نه تغییر، نه درج |

اگر نمی‌خواهید کاربر دیتابیس ساخته شود، تیک بخش «اتصال مستقیم اندروید به SQL Server» را
بردارید؛ سامانه بدون آن هم نصب می‌شود و اسکریپت دستی ساخت کاربر در پوشهٔ `docs` هست.

## ۱۴) بررسی‌هایی که روی همین فایل انجام شده

* نصب‌کننده با NSIS 3.03 (یونیکد) **بی‌خطا و بی‌هشدار** کامپایل شده است.
* متن‌های فارسی در فایل نهایی به‌صورت UTF-16 ذخیره می‌شوند (با یک تست کنترل‌شده تأیید شد).
* کد QR با یک **دیکودر مستقل (OpenCV)** خوانده شد و متنش دقیقاً همان کارت اتصال بود ✓.
* مسیرهای سرور اندروید با تست واقعی HTTP بررسی شد: `/api/config` بدون رمز،
  `/api/direct-sql/setup` با کد درست ۲۰۰ و با کد غلط ۴۰۳، و کد در لاگ ستاره‌دار ✓.
* ۷۲ فایل (۱٫۲۶ مگابایت) داخل نصب‌کننده بسته‌بندی شده‌اند؛ فهرست کامل با `makensis -V4` دیده می‌شود.
* ⛔ **آنچه تست نشده:** اجرای واقعی روی ویندوز (فایل در لینوکس ساخته شده). چک‌لیست بخش ۹ را یک‌بار اجرا کنید.

## ۱۵) پورت ۹۵۹۵، انتخاب دیتابیس از لیست زنده و تیک بررسی سلامت

### پورت پیش‌فرض ۹۵۹۵
* سامانه روی پورت **۹۵۹۵** بالا می‌آید (سرویس خودش؛ **بدون IIS**).
* قاعدهٔ فایروال برای ۹۵۹۵ فقط روی **شبکهٔ محلی** باز می‌شود.
* آدرس نهایی سامانه: `http://<آی‌پی-سرور>:9595/api` (پنل: `.../api/health`).

### IIS از این نسخه حذف شد
* نصب‌کننده **هیچ کاری با IIS ندارد**: نه سایت می‌سازد، نه پیکربندی IIS را می‌خواند/تغییر می‌دهد،
  نه ماژول URL Rewrite/ARR نصب می‌کند.
* بخش «پروکسی IIS» از فهرست بخش‌ها، تیک‌ها و کلیدهای پاسخ حذف شده است.
* در حذف نصب فقط اگر سایت باقی‌ماندهٔ نسخه‌های قبلی با نام دقیق `VizitorAPI` وجود داشته باشد، پاک می‌شود.

### صفحهٔ «دیتابیس حسابداری» (صفحهٔ دوم ویزارد)
1. سرور/پورت SQL (پیش‌فرض `localhost:1433`) و نام کاربری + کلمهٔ عبور **با دسترسی کامل**.
2. دکمهٔ **«دریافت لیست دیتابیس‌ها»** → لیست دیتابیس‌های آن سرور در کادر روبه‌رو می‌آید (خودکار، فقط خواندنی).
3. دیتابیس حسابداری را انتخاب می‌کنید (مثلاً `Meelano`) → همین به `-Answers` به‌عنوان `android/erpdb` می‌رود
   و همهٔ کارهای اتصال اندروید روی آن انجام می‌شود.
4. تیک **«بررسی سلامت اتصال و جدول‌های لازم در پایان نصب»** (پیش‌فرض روشن) → در پایان نصب، اتصال و وجود
   `sys_users`، `CUSTOMERS`، `inventory`، `custgroup`، `forosh_price`، `ka_act`، `sailfact_pish`،
   `subsact_pish`-ها، `sal_mali` و پروسیجرهای نوشتن بررسی و در گزارش نهایی سبز/زرد نمایش داده می‌شود
   (`C:\ProgramData\Vizitor\sql_health.json`).

> اگر ابزار `sql_admin_tools.py` به‌هر دلیل کار نکند (پایتون نبود، سرور خاموش)، لیست خالی می‌ماند و
> نام دیتابیس را می‌توانید دستی بنویسید؛ نصب متوقف نمی‌شود.

### اتصال اندروید: فقط مستقیم
* مسیر دادهٔ برنامهٔ اندروید **فقط** `SQL Server:1433` است؛ بخش اتصال با API از این مسیر حذف شده.
* کارت اتصال و QR فقط اطلاعات مستقیم را دارند:
  `vizitor://c?h=<آی‌پی داخلی>&p=1433&d=<دیتابیس>&u=<کاربر محدود>&H=<آی‌پی ثابت>`
* در برنامه: یک‌بار اعتبارنامهٔ کامل دیتابیس → «دریافت لیست دیتابیس‌ها» → انتخاب دیتابیس → خواندن تنظیمات
  از دیتابیس → «بررسی سلامت اتصال» → از این پس هر ویزیتور با نام کاربری و کلمهٔ عبور خودش وارد می‌شود.
* کد نمونهٔ Kotlin این دو مرحله در [ANDROID_INTEGRATION.md](../ANDROID_INTEGRATION.md) آمده است.

### چیزهایی که باید یک‌بار روی ویندوز تست شود
- [ ] دکمهٔ «دریافت لیست دیتابیس‌ها» لیست را درست پر می‌کند (با کاربر `sa` و بعد با کاربر محدود).
- [ ] هیچ تغییری در IIS دیده نمی‌شود (نصب‌کننده به IIS دست نمی‌زند).
- [ ] `http://<آی‌پی>:9595/api/health` در مرورگر جواب می‌دهد و پنل باز می‌شود.
- [ ] گزارش نهایی: خط «سلامت اتصال: تایید شد ✓».

## ۱۶) آیا برای اتصال اندروید به SQL Server، IIS لازم است؟  **خیر**

| کار | به IIS نیاز دارد؟ | چه چیزی لازم است |
|---|---|---|
| **اتصال مستقیم برنامهٔ اندروید به دیتابیس (۱۴۳۳)** — خواندن جدول‌ها، قیمت‌ها، ثبت و ارسال پیش‌فاکتور | ❌ **نه** | فقط SQL Server روی همان سرور + باز بودن پورت **۱۴۳۳** برای شبکهٔ محلی + کاربر دیتابیس |
| ورود ویزیتور با نام کاربری/کلمهٔ عبور خودش | ❌ نه | همان اتصال مستقیم (`dbo.sys_users`) |
| پنل وب مدیریت، `/api/health`، فعال‌سازی سامانه، نمایش وضعیت | ❌ نه | سرویس خود سامانه روی پورت ۹۵۹۵ |
| کد QR / کارت اتصال | ❌ نه | فایل‌های ساخته‌شده در `C:\Vizitor\setup` |

**در نسخهٔ ۱.۲ چه چیزی تغییر کرد:**
* **IIS کاملاً حذف شد** — نه در ویزارد، نه در موتور نصب (`install.ps1`)، نه در مسیر دادهٔ برنامهٔ اندروید.
* APIهای مخصوص «خودپیکربندی اپ» (`/api/direct-sql/setup` و بلوک `direct_sql` در `/api/config`) هم
  برداشته شدند؛ اپ اندروید هیچ‌گاه از طریق API تنظیم نمی‌شود.
* ویزارد حالا فقط دو صفحهٔ تنظیم دارد: **سرور سامانه** (آدرس + پورت ۹۵۹۵) و **دیتابیس حسابداری**
  (سرور/کاربر/رمز → لیست دیتابیس‌ها → انتخاب → تیک سلامت).
* نوار وضعیت: «اتصال اندروید: مستقیم به SQL Server روی پورت ۱۴۳۳ — بدون IIS و بدون API».

**نتیجهٔ عملی:** برای کار ویزیتورها فقط این‌ها لازم است:
1. سرویس SQL Server در حال اجرا باشد و پورت ۱۴۳۳ در شبکهٔ محلی باز باشد (نصب‌کننده این قاعده را می‌سازد).
2. کاربر دیتابیس با گرنت‌های لازم (`vizitor_android` که نصب‌کننده می‌سازد، یا کاربر خود برنامهٔ حسابداری).
3. برنامهٔ اندروید فقط یک‌بار نشانی سرور (آی‌پی داخلی یا ثابت) + کاربر/رمز دیتابیس را بگیرد، لیست دیتابیس‌ها را بگیرد و دیتابیس حسابداری را انتخاب کند.

> پنل وب هم روی `http://<آی‌پی-سرور>:9595` بالا می‌آید و به IIS کاری ندارد؛ پس هیچ قابلیتی از دست نمی‌رود.

## ۱۸) نسخهٔ ۱.۳ — دو نشانی سرور، بدون دیتابیس اجباری، انتخاب دیتابیس از لیست

### هیچ دیتابیسی اجباری نیست
* «میلانو» به‌عنوان پیش‌فرض از همه‌جا برداشته شد (`install.ps1`، `vizitor.nsi` و `android_connect.py`).
* در صفحهٔ «دیتابیس حسابداری» اگر چیزی انتخاب نشده باشد، نصب اجازهٔ ادامه نمی‌دهد و می‌گوید
  «دیتابیس برنامه را از لیست انتخاب کنید» — هر دیتابیسی روی همان سرور قابل انتخاب است.
* اگر این بخش در ویزارد تیک نخورده باشد، نصب انجام می‌شود و بعداً میان‌بر «اتصال مستقیم SQL» همین کار را می‌کند.

### اتصال از بیرون شبکه (آی‌پی اختصاصی) + اتصال داخلی
صفحهٔ دوم ویزارد حالا این‌ها را می‌پرسد:

| فیلد | توضیح |
|---|---|
| سرور / پورت SQL Server | پیش‌فرض `localhost` و **۱۴۳۳** |
| نام کاربری + کلمهٔ عبور SQL | همان کاربری که به دیتابیس دسترسی کامل دارد |
| **آی‌پی اختصاصی/اینترنتی سرور SQL (اختیاری)** | برای اتصال از بیرون شبکه؛ در کارت اتصال و QR می‌آید |
| **تیک «اجازهٔ اتصال به ۱۴۳۳ از بیرون شبکه»** | اگر روشن باشد، قاعدهٔ فایروال پورت ۱۴۳۳ برای «هر آدرس» ساخته می‌شود؛ اگر خاموش، فقط شبکهٔ محلی |
| دکمهٔ «دریافت لیست دیتابیس‌ها» + لیست | انتخاب دیتابیس برنامه از روی همان سرور |

> ⚠ اگر تیک بیرون‌شبکه را می‌زنید: پورت ۱۴۳۳ را در روتر به همین سرور فوروارد کنید و برای امنیت،
> کاربر محدود `vizitor_android` با رمز قوی را در برنامه استفاده کنید (یا فقط IP های ویزیتورها را مجاز کنید).
> برای داخل فروشگاه، همان آی‌پی داخلی (`192.168.1.x`) کافی است و نیازی به این تیک نیست.

### فایل `connect.txt` (بدون رمز) حالا هر دو نشانی را دارد
```
androidsqlserver=192.168.1.150,1433
androidsqlserverpublic=37.143.147.19,1433     ← اگر وارد کرده باشید
androidexternal=1                              ← اگر تیک بیرون‌شبکه زده شده باشد
```

### در برنامهٔ اندروید (پیاده‌شده در `android-sql-direct/`)
۱) انتخاب روش اتصال: **از اینترنت (آی‌پی اختصاصی)** یا **شبکهٔ داخلی** — با پورت پیش‌فرض ۱۴۳۳.
۲) وارد کردن نام کاربری و کلمهٔ عبور SQL Server.
۳) دکمهٔ **«تأیید و دریافت لیست دیتابیس‌ها»** → لیست دیتابیس‌های همان سرور.
۴) انتخاب دیتابیس برنامه (چیپ‌های قابل لمس).
۵) **«اعمال تنظیمات و تست اتصال»** → ذخیرهٔ رمزنگاری‌شده + بررسی سلامت → ورود ویزیتور با حساب خودش.

## ۱۹) نسخهٔ ۱.۳ — ظاهر تازه، بخش انتخاب دیتابیس با تایپ دستی، و نام سازنده

### بخش انتخاب دیتابیس حالا یک بخش واقعی است (صفحهٔ سوم ویزارد)
* **فهرست دیتابیس‌های سرور**: دکمهٔ آبی «دریافت فهرست دیتابیس‌ها» + کادر فهرست
  (لیست از `sys.databases` همان سرور با کاربر/رمز وارد‌شده گرفته می‌شود).
* **کادر تایپ دستی**: `۲) نام دیتابیس برنامه (حسابداری) — انتخاب از فهرست یا تایپ دستی`
  → اگر سرور در دسترس نبود یا پایتون نصب نبود، دستی بنویسید؛ نصب به‌خاطر این متوقف نمی‌شود.
* با کلیک روی هر نام در فهرست، همان نام خودکار در کادر تایپ می‌آید.
* دکمهٔ سبز **«تأیید نام دیتابیس»**: بررسی می‌کند نام در فهرست همان سرور هست یا نه و
  نتیجه را سبز/زرد نشان می‌دهد. تا نام تأیید نشود، «بعدی» اجازهٔ عبور نمی‌دهد.
* کادر «دیتابیس خود ویزیتور» و تیک «بررسی سلامت» از پایین صفحه به یک ردیف جمع‌شدند تا
  فهرست جای بیشتری بگیرد. **هیچ دیتابیسی اجباری نیست.**

### صفحهٔ جدید «اتصال به SQL Server» (صفحهٔ دوم)
* سرور/پورت (پیش‌فرض ۱۴۳۳) + **دو رادیو**: «کاربر SQL Server» یا «حساب ویندوز همین سرور».
* نام کاربری و کلمهٔ عبور (با احراز هویت ویندوز، خودکار غیرفعال می‌شوند).
* **آی‌پی اختصاصی/اینترنتی سرور** + تیک **«اجازهٔ اتصال به ۱۴۳۳ از بیرون شبکه»**.
* دکمهٔ **«تست اتصال و شمردن دیتابیس‌ها»** با نمایش نتیجه در همان صفحه
  (سبز = اتصال برقرار و تعداد دیتابیس‌ها، قرمز = علت خطا).

### ظاهر: کارت‌های رنگی، فونت درشت‌تر، راست‌به‌چپ کامل
* صفحه‌های ویزارد حالا **تمام‌پنجره** ساخته می‌شوند (`nsDialogs::Create 1044` +
  `muiPageLoadFullWindow`) — قبلاً بخش‌های پایین صفحه بیرون از کادر ۳۰۰×۱۴۰ بریده می‌شدند
  و همین باعث می‌شد «بخش انتخاب دیتابیس» دیده نشود.

  در اجرای بعدی، کادرها با همان مقادیر پر می‌شوند (`LoadLastWizard`).
* پیام ابتدایی حالا فقط دو گزینهٔ ساده دارد: **بله = به‌روزرسانی و تعمیر** / **خیر = نصب تازه**؛
  در هر دو حالت صفحه‌های تنظیمات نمایش داده می‌شوند (قبلاً «بله» ویزارد را کاملاً رد می‌کرد و
  به همین دلیل کاربر هیچ صفحهٔ تنظیماتی نمی‌دید).
* رمز SQL Server **هرگز** در `wizard_last.ini` نوشته نمی‌شود.

## ۲۱) پیش‌نمایش طرح سه‌بعدی پنل مدیریت

برای اینکه سبک سه‌بعدی را قبل از ساخت کامل ببینید، یک **پیش‌نمایش زندهٔ طرح پنل** هم گذاشته شد:

```
installer/panel-preview/index.html      ← یک فایل مستقل (بدون اینترنت، بدون کتابخانهٔ بیرونی)
```

* باز کردن: روی فایل دوبار کلیک کنید یا در پوشه‌اش اجرا کنید:  `python -m http.server 8010`
  و بعد `http://127.0.0.1:8010` را در مرورگر باز کنید.
* چه چیزهایی دارد: کارت‌های سه‌بعدی با چرخش پارالاکس با حرکت موس، دکمه‌های برجستهٔ فشاری،
  تمبر طلایی سه‌بعدی، نور متحرک پس‌زمینه، چیپ‌های انتخاب دیتابیس، سنجهٔ سلامت، شناسنامهٔ سازنده
  («میلاد یقوبی / Meelano Studio Design»).
* این فایل **فقط طرح بصری** است؛ داده‌هایش نمونه‌اند و به دیتابیس وصل نیست. ارتباط واقعی پنل با
  `install.ps1` و `api/server.py` انجام می‌شود.
* همان زبان بصری در **ویزارد نصب** هم پیاده شد (نوار گرادیانی + خط طلایی، کارت‌های برجسته با لبهٔ
  روشن، دکمه‌های با پایهٔ تیره، نوار امضای سازنده).

> اگر این سبک را تأیید کنید، همین زبان بصری را روی پنل واقعی (صفحه‌ای که روی پورت ۹۵۹۵ سرو می‌شود)
> هم پیاده می‌کنم؛ فایل پیش‌نمایش طوری نوشته شده که مستقیماً قابل استفاده باشد.

## ۲۲) پس‌زمینهٔ یکدست سرمه‌ای + فونت وزیرمتن + بازچینش کامل «بخش نمایش»

### پس‌زمینهٔ یکدست
* همهٔ گرادیان‌ها و نور متحرک پس‌زمینه حذف شد؛ صفحهٔ پیش‌نمایش روی **یک رنگ سرمه‌ای ثابت** می‌نشیند:
  `--navy: #0B2138` و کارت‌ها یک پله روشن‌تر (`#102A45` و `#143254`).
* در ویزارد هم **نوار بالا و نوار پایین یک رنگ شدند** (`COL_BAND = 0x102A45`) و پشت کارت‌ها یک
  **پس‌زمینهٔ سرمه‌ای تمام‌صفحه** (`COL_PAGE = 0x0B2138`) کشیده شد؛ دیگر گرادیان سه‌رنگ وجود ندارد.

### فونت وزیرمتن (Vazirmatn)
| جا | جزئیات |
|---|---|
| ویزارد | `Vazirmatn-Regular.ttf` و `Vazirmatn-Bold.ttf` داخل نصب‌کننده هستند، در `.onInit` در `$PLUGINSDIR` باز می‌شوند و با `gdi32::AddFontResource` **فقط برای همین نصب‌کننده** بارگذاری می‌شوند (روی ویندوز نصب نمی‌شود) و در `.onGUIEnd` آزاد می‌شوند. فونت‌ها: تیتر ۱۳ / سرتیتر ۱۱ / متن ۱۰ / راهنما ۹ / دکمه ۱۱ |
| پیش‌نمایش پنل | با `@font-face` و فایل‌های `woff2` محلی (`installer/panel-preview/fonts/`) — بدون نیاز به اینترنت |
| مجوز | `SIL OFL 1.1` — فایل `OFL.txt` هم کنار فونت‌ها و هم در بستهٔ راهنماهای نصب (`C:\Vizitor\docs\Vazirmatn-OFL.txt`) قرار می‌گیرد. نسخهٔ بستهٔ فونت: `vazirmatn 33.0.3` |

### بازچینش کامل بخش نمایش (پیش‌نمایش پنل)
* گرید **۱۲ ستونی** با یک عرض بیشینهٔ ثابت (۱۱۸۰px) و مقیاس فاصلهٔ یکدست
  (`--s1..--s6`) و شعاع‌های یکدست کارت/کادر/چیپ.
* **چهار کاشی آماری** در بالای صفحه: تعداد دیتابیس‌های سرور، ویزیتورهای فعال، پیش‌فاکتورهای ماه،
  وضعیت فعال‌سازی (هر کاشی با آیکون، عنوان و مقدار درشت طلایی).
* **ردیف اصلی**: «اتصال به SQL Server» (سرور/پورت، کاربر/رمز، آی‌پی اختصاصی، دکمهٔ تست اتصال و
  ردیف وضعیت رنگی) کنار «انتخاب دیتابیس برنامه» (چیپ‌های فهرست، دکمهٔ دریافت فهرست، کادر تایپ دستی،
  دکمهٔ تأیید طلایی و ردیف وضعیت).
* **ردیف دوم**: «بررسی سلامت» با حلقهٔ گرافیکی درصد + جدول خلاصه، «فعال‌سازی سامانه»
  (کد + ثبت/بعداً)، «گزارش‌ها و لاگ‌ها».
* **کارت شناسنامه** تمام‌عرض با تمبر طلایی و نام سازنده و گروه، سپس **پانوشت امضای سازنده**.
* چیدمان واکنش‌گرا: در عرض‌های کمتر، کاشی‌ها ۶ ستونه و صفحه‌های اصلی ۱۲ ستونه می‌شوند
  (بریک‌پوینت‌های ۱۰۸۰px و ۶۶۰px)، همه‌چیز راست‌به‌چپ و بدون سرریز.
* اجزای تعاملی: چیپ‌های دیتابیس نام را به کادر تایپ منتقل می‌کنند و دکمه‌ها پیام وضعیت (toast)
  نشان می‌دهند تا رفتار واقعی پنل قابل لمس باشد.

### ۲۲-۱) دو پیش‌نمایش، دو کار متفاوت
| فایل | چه چیزی را نشان می‌دهد |
|---|---|
| `installer/panel-preview/wizard.html` | **ویزارد نصب**: صفحهٔ خوش‌آمد، چهار گام سفارشی (سرور / اتصال SQL / انتخاب دیتابیس / فعال‌سازی) و صفحهٔ پایان — با همان نوار سرصفحه‌ای و تصویر کناری‌ای که داخل `exe` هستند، و همان متن‌ها و چیدمان `vizitor.nsi` |
| `installer/panel-preview/index.html` | **پنل مدیریت** (طرح سه‌بعدی سرمه‌ای با کاشی‌های آماری، اتصال، دیتابیس، سلامت، فعال‌سازی، شناسنامه) — داده‌های نمونه |

هر دو صفحه یک یادداشت بالای خود دارند که توضیح می‌دهد «پیش‌نمایش طرح» هستند و
**نصب‌کنندهٔ واقعی، همان فایل `release/Vizitor-Setup-1.0.0.exe` ویندوز است**؛ پیش‌نمایش‌ها
فقط برای تأیید ظاهر پیش از نصب‌اند و به دادهٔ واقعی وصل نیستند.
