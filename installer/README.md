# نصب‌کنندهٔ ویندوز ویزیتور — `Vizitor-Setup.exe`

فایل نصب تک‌فایلی سامانهٔ ویزیتور برای **ویندوز ۷ / ۸ / ۸.۱ / ۱۰ / ۱۱**
(۳۲ و ۶۴ بیتی) با رابط فارسی راست‌به‌چپ، آیکن اختصاصی، **انتخاب بخش‌ها با
تیک** و **کد فعال‌سازی**.

| | |
|---|---|
| نام فایل | `release/Vizitor-Setup-1.0.0.exe` |
| حجم | 613٬349 بایت (≈ ۵۹۹ کیلوبایت) |
| بررسی سلامت | `certutil -hashfile Vizitor-Setup-1.0.0.exe SHA256` (هش در هر ساخت دوباره تغییر می‌کند) |
| موتور | NSIS 3.03 (Unicode) — MUI2 |
| نیازمند | دسترسی Administrator (خود نصب‌کننده درخواست می‌کند) |
| فایل‌های همراه | `install.ps1`، `api/*.py`، `database/*.sql`، بستهٔ فارسی مهاجرت (`android-sql-direct`)، مولد QR (segno، مجوز BSD-3) |

> ⚠ این فایل داخل سندباکس لینوکس ساخته شده است. ساخت و بسته‌بندی و امضای
> فایل‌ها درست است، اما **اجرای واقعی آن روی ویندوز را باید یک‌بار خودتان
> تست کنید**؛ بخش «چک‌لیست تست» پایین همین فایل را ببینید.

## ۲) صفحه‌های نصب‌کننده

1. **خوش‌آمد** — معرفی و تصویر اختصاصی ویزیتور
2. **شرایط استفاده** — متن فارسی
3. **انتخاب بخش‌ها** — همان جدول بالا (تیک‌ها + توضیح هر بخش)
4. **پوشهٔ نصب** — پیش‌فرض `C:\Vizitor`
5. **تنظیمات سرور و دیتابیس** — آدرس/IP سرور (خودکار از شبکه تشخیص داده
   می‌شود)، پورت API، تیک IIS، سرور/پورت/کاربر/رمز SQL Server (رمز با
   `***` نمایش داده می‌شود)، نام دیتابیس سامانه، نام دیتابیس ERP (پیش‌فرض
   `Meelano`) و **پیش‌نمایش زندهٔ آدرس نهایی API**
6. **کد فعال‌سازی** — کد را وارد کنید یا تیک «فعلاً کد ندارم» را بزنید
7. **نصب** — لاگ زندهٔ همهٔ کارها (همان خروجی فارسی `install.ps1`)
8. **پایان** — آدرس API، میان‌بر بازکردن پنل، نمایش `connect.txt`، لینک پوشهٔ راهنما

## ۳) پشت صحنه (چطور به هم وصل می‌شوند)

```
Vizitor-Setup.exe (NSIS)
   ├─ preflight.ps1  →  ip / python / sql / iis / admin / ps  را تشخیص می‌دهد
   ├─ پاسخ صفحه‌ها   →  %TEMP%\<plugins>\answers.ini  (INI ساده، بدون مشکل escape)
   └─ install.ps1 -Answers answers.ini -AppHome <پوشه> [-Skip…ها]
            ├─ پیش‌نیازها، انتشار فایل‌ها، config.json
            ├─ پروکسی IIS (اختیاری) و فایروال
            ├─ provision_sqlserver.py  (جداول سامانه، غیرتلفیقی)
            ├─ provision_android_sql.py (کاربر vizitor_android + گرنت‌ها)
            ├─ سرویس VizitorAPI + بازرسی/تعمیر تا ۴ دور
            └─ connect.txt  (آدرس API و مشخصات، بدون رمز)
```

`install.ps1` همان نصب‌کنندهٔ هوشمند قبلی است و بدون هیچ پارامتری هنوز
دقیقاً مثل قبل و کاملاً پرسشی کار می‌کند؛ پارامترهای جدید فقط برای زمانی
است که نصب‌کنندهٔ گرافیکی آن را صدا می‌زند.

## ۴) امنیت

* **رمز SQL Server هیچ‌جا نمایش داده نمی‌شود**: در صفحهٔ مخصوص با `***`
  گرفته می‌شود، در `answers.ini` موقت است، بعد از نصب همان فایل پاک
  می‌شود و در لاگ‌ها/گزارش‌ها/خطاها چاپ نمی‌شود.
* رمز اتصال مستقیم اندروید به‌صورت خودکار ساخته می‌شود و فقط در
  `C:\ProgramData\Vizitor\android_app_password.txt` با ACL محدود
  (SYSTEM + Administrators) ذخیره می‌شود؛ فقط مسیر فایل چاپ می‌شود.
* پوشهٔ `C:\ProgramData\Vizitor` (که `config.json` و رمز دیتابیس در آن است)
  در پایان نصب ACL محدود می‌گیرد.
* قاعدهٔ فایروال پورت ۱۴۳۳ فقط برای `LocalSubnet` باز می‌شود (نه اینترنت).
* رفتار دیتابیس **غیرتلفیقی** است: فقط `CREATE … IF NOT EXISTS`؛ هیچ
  `DROP`/`TRUNCATE`/`ALTER` روی اشیای موجود، و هیچ تغییری در تنظیمات سرور.

## ۵) مسیرهای نصب

```
C:\Vizitor\                ← پوشهٔ نصب (AppHome؛ قابل تغییر در ویزارد)
├─ setup\                  ← بستهٔ اصلی: install.ps1، api\، database\، preflight.ps1، connect.txt
├─ tools\                  ← میان‌برهای bat: بازرسی، شروع/توقف سرویس، پنل، اتصال مستقیم SQL
├─ docs\                    ← راهنماهای فارسی + docs\migration (کل بستهٔ android-sql-direct)
├─ api\ iis\ run.bat       ← برنامهٔ منتشرشدهٔ API (توسط install.ps1)
└─ uninstall.exe
C:\ProgramData\Vizitor\    ← config.json، vizitor.log، vizitor.pid، android_app_password.txt
```

## ۶) حذف نصب

`uninstall.exe` (یا «برنامه‌ها و ویژگی‌ها») این کارها را می‌کند:
توقف و حذف سرویس `VizitorAPI`، حذف قاعده‌های فایروال `Vizitor API` و
`Vizitor SQL 1433`، حذف سایت/اپلیکیشن IIS **فقط اگر خود ویزیتور ساخته
باشد**، حذف میان‌برها و فایل‌های برنامه.
از شما می‌پرسد که `C:\ProgramData\Vizitor` هم پاک شود یا نه — و
**داده‌های دیتابیس در هر حالت دست‌نخورده می‌مانند** (هیچ جدولی حذف نمی‌شود).

## ۷) ساخت دوبارهٔ فایل نصب

**روی ویندوز:**
```
1. NSIS 3 را نصب کنید:  https://nsis.sourceforge.io/Download
2. در ریشهٔ مخزن اجرا کنید:   installer\build.bat
3. خروجی:  release\Vizitor-Setup-1.0.0.exe

```


آیکن و تصاویر ویزارد از `installer/assets/` می‌آیند و با
`python3 installer/assets/make_branding.py` بازتولید می‌شوند
(`vizitor.ico` چند-اندازه: ۱۶ تا ۲۵۶ پیکسل).

## ۸) نصب بی‌صدا (اختیاری، برای مدیر سیستم)

```
Vizitor-Setup-1.0.0.exe /S
```
در حالت بی‌صدا همهٔ صفحه‌ها رد می‌شوند و `install.ps1` با مقادیر پیش‌فرض
(IP شناسایی‌شده، `localhost`/`1433`، کاربر `sa`، دیتابیس `vizitor`) اجرا

گرافیکی استفاده کنید.

## ۱۱) اتصال اندروید در یک قدم: کارت اتصال و کد QR

پس از نصب (اگر بخش «اتصال مستقیم اندروید» تیک خورده باشد) این فایل‌ها ساخته می‌شوند:

```
C:\Vizitor\setup\android-connect.png     ← کد QR ؛ با برنامه اسکن کنید
C:\Vizitor\setup\android-connect.txt     ← کارت متنی فارسی (سرور، دیتابیس، کاربر، کد راه‌اندازی)
C:\Vizitor\setup\android-connect.json    ← همان اطلاعات برای برنامه‌نویس اندروید (بدون رمز)
C:\ProgramData\Vizitor\android_config.json  ← نسخهٔ کامل با رمز (دسترسی: فقط SYSTEM و Administrators)
```

**ویزیتور هیچ چیزی تنظیم نمی‌کند:** QR را یک‌بار با برنامه اسکن می‌کند (یا فقط نشانی سرور را
می‌زند) و بعد فقط **نام کاربری و کلمهٔ عبور خودش** را وارد می‌کند.

محتوای QR:

```
vizitor://c?h=<سرور>&p=1433&d=<دیتابیس ERP>&u=vizitor_android&t=<کد راه‌اندازی>&a=<آدرس API>
```

**سمت سرور (همین حالا کار می‌کند و تست شده):**

| درخواست | پاسخ |
|---|---|
| `GET http://سرور/api/config` | `direct_sql` بدون رمز: سرور، پورت، دیتابیس، کاربر، `token_required` |
| `GET http://سرور/api/direct-sql/setup` با هدر `X-Vizitor-Token: <کد>` | همان + `password` و `connection_string` آمادهٔ JDBC |
| همان بدون کد یا با کد غلط | `403 bad_setup_code` (و ۱۰ تلاش غلط = یک دقیقه قفل) |

* کد راه‌اندازی در نصب ساخته می‌شود، در QR و کارت متنی است و **در لاگ‌ها ستاره‌دار (`***`) می‌شود**.
* اگر می‌خواهید بدون کد باشد (فقط شبکهٔ محلی و به‌خواست خودتان): در
  `C:\ProgramData\Vizitor\config.json` داخل `direct_sql` مقدار `"setup_token": ""` بگذارید و
  `"allow_anonymous": true` را ست کنید. **پیش‌فرض امن است.**
* اگر نشانی سرور یا کد عوض شد، میان‌بر «اتصال مستقیم SQL» را یک‌بار اجرا کنید: QR و کارت دوباره ساخته می‌شوند.

## ۱۲) جایگزینی نصب قبلی — دقیقاً چه چیزی پاک می‌شود

اگر نصب قبلی پیدا شود، در همان ابتدا می‌پرسد:

| انتخاب | نتیجه |
|---|---|
| **بله** = بازرسی و تعمیر | هیچ فایلی پاک نمی‌شود؛ فقط همه‌چیز بررسی و در صورت نیاز تعمیر می‌شود |
| **خیر** = پیکربندی دوباره | فایل‌های *برنامه* جایگزین می‌شوند: `setup`، `api`، `iis`، `docs`، `tools`، `run.bat` (اول سرویس متوقف می‌شود) |
| **انصراف** | نصب انجام نمی‌شود |

در هر حالت این‌ها **دست‌نخورده** می‌مانند:

* `C:\ProgramData\Vizitor` → `config.json`، لاگ‌ها، `vizitor.db` (اگر sqlite)، فایل رمز، کارت‌های اتصال.
  (اگر پاک کردنش را بخواهید، فقط در «حذف نصب» و با پرسش صریح انجام می‌شود.)
* **دیتابیس SQL Server** → هیچ جدول/داده/شیئی پاک یا بازنویسی نمی‌شود (بخش بعدی).

## ۱۳) «بدون هیچ تغییر در دیتابیس» یعنی چه؟

| کار | تغییر در ERP؟ |
|---|---|
| بررسی دسترسی و نسخهٔ SQL Server | فقط خواندن |
| ساخت دیتابیس/جداول خود سامانهٔ ویزیتور (`provision_sqlserver.py`) | فقط `CREATE` برای چیزهایی که **نیستند**؛ هیچ `DROP`/`ALTER`/`TRUNCATE` |
| کاربر اتصال اندروید (`provision_android_sql.py`) | ساخت **لاگین/یوزر** و `GRANT` (فقط اگر نباشد؛ رمز لاگین موجود هرگز عوض نمی‌شود) |
| جدول‌های ERP (Meelano) | **هیچ تغییری** — نه ساخت، نه تغییر، نه درج |

اگر نمی‌خواهید کاربر دیتابیس ساخته شود، تیک بخش «اتصال مستقیم اندروید به SQL Server» را
بردارید؛ سامانه بدون آن هم نصب می‌شود و اسکریپت دستی ساخت کاربر در پوشهٔ `docs` هست.

## ۱۴) بررسی‌هایی که روی همین فایل انجام شده

* نصب‌کننده با NSIS 3.03 (یونیکد) **بی‌خطا و بی‌هشدار** کامپایل شده است.
* متن‌های فارسی در فایل نهایی به‌صورت UTF-16 ذخیره می‌شوند (با یک تست کنترل‌شده تأیید شد).
* کد QR با یک **دیکودر مستقل (OpenCV)** خوانده شد و متنش دقیقاً همان کارت اتصال بود ✓.
* مسیرهای سرور اندروید با تست واقعی HTTP بررسی شد: `/api/config` بدون رمز،
  `/api/direct-sql/setup` با کد درست ۲۰۰ و با کد غلط ۴۰۳، و کد در لاگ ستاره‌دار ✓.
* ۷۲ فایل (۱٫۲۶ مگابایت) داخل نصب‌کننده بسته‌بندی شده‌اند؛ فهرست کامل با `makensis -V4` دیده می‌شود.
* ⛔ **آنچه تست نشده:** اجرای واقعی روی ویندوز (فایل در لینوکس ساخته شده). چک‌لیست بخش ۹ را یک‌بار اجرا کنید.

## ۱۵) نسخهٔ ۱.۱ — پورت ۹۵۹۵، پاک‌سازی IIS، انتخاب دیتابیس از لیست و تیک سلامت

### پورت پیش‌فرض ۹۵۹۵
* سایت IIS ویزیتور روی پورت **۹۵۹۵** ساخته می‌شود و ترافیک را به API داخلی (۹۵۹۶ و به بعد) می‌دهد.
* اگر IIS را تیک نزنید، خودِ API روی همان **۹۵۹۵** گوش می‌دهد.
* قاعدهٔ فایروال برای ۹۵۹۵ فقط روی **شبکهٔ محلی** باز می‌شود.
* آدرس نهایی سامانه: `http://<آی‌پی-سرور>:9595/api` (پنل: `.../api/health`).

### پاک‌سازی کامل IIS (تیک پیش‌فرض روشن)
اگر تیک **«پاک‌سازی کامل تنظیمات موجود IIS و ساخت دوبارهٔ سایت ویزیتور»** روشن باشد:
1. **اول پشتیبان**: خروجی `appcmd list` برای `site/app/apppool/vdir/config` در
   `C:\ProgramData\Vizitor\iis-backup-<تاریخ>` ذخیره و یک `appcmd add backup vizitor-before-install` هم گرفته می‌شود.
2. سپس **همهٔ سایت‌ها** و استخرهای برنامه (به‌جز `DefaultAppPool`) حذف می‌شوند؛ نام هر موردی که حذف می‌شود
   در لاگ نصب می‌آید.
3. بعد یک سایت تازهٔ `Vizitor` با استخر `VizitorPool` (No Managed Code) روی پورت ۹۵۹۵ ساخته می‌شود و
   ماژول‌های URL Rewrite و ARR در صورت نبود با winget نصب می‌شوند.
* بازگردانی پشتیبان: `%windir%\system32\inetsrv\appcmd.exe restore backup vizitor-before-install`
  یا استفاده از فایل‌های XML پوشهٔ پشتیبان.
* اگر نمی‌خواهید چیزی از IIS پاک شود، تیک را **بردارید**؛ آن‌وقت فقط سایت/اپ جدید ساخته می‌شود.

### صفحهٔ «دیتابیس حسابداری» (صفحهٔ دوم ویزارد)
1. سرور/پورت SQL (پیش‌فرض `localhost:1433`) و نام کاربری + کلمهٔ عبور **با دسترسی کامل**.
2. دکمهٔ **«دریافت لیست دیتابیس‌ها»** → لیست دیتابیس‌های آن سرور در کادر روبه‌رو می‌آید (خودکار، فقط خواندنی).
3. دیتابیس حسابداری را انتخاب می‌کنید (مثلاً `Meelano`) → همین به `-Answers` به‌عنوان `android/erpdb` می‌رود
   و همهٔ کارهای اتصال اندروید روی آن انجام می‌شود.
4. تیک **«بررسی سلامت اتصال و جدول‌های لازم در پایان نصب»** (پیش‌فرض روشن) → در پایان نصب، اتصال و وجود
   `sys_users`، `CUSTOMERS`، `inventory`، `custgroup`، `forosh_price`، `ka_act`، `sailfact_pish`،
   `subsact_pish`-ها، `sal_mali` و پروسیجرهای نوشتن بررسی و در گزارش نهایی سبز/زرد نمایش داده می‌شود
   (`C:\ProgramData\Vizitor\sql_health.json`).

> اگر ابزار `sql_admin_tools.py` به‌هر دلیل کار نکند (پایتون نبود، سرور خاموش)، لیست خالی می‌ماند و
> نام دیتابیس را می‌توانید دستی بنویسید؛ نصب متوقف نمی‌شود.

### اتصال اندروید: فقط مستقیم
* مسیر دادهٔ برنامهٔ اندروید **فقط** `SQL Server:1433` است؛ بخش اتصال با API از این مسیر حذف شده.
* کارت اتصال و QR فقط اطلاعات مستقیم را دارند:
  `vizitor://c?h=<آی‌پی داخلی>&p=1433&d=<دیتابیس>&u=<کاربر محدود>&H=<آی‌پی ثابت>`
* در برنامه: یک‌بار اعتبارنامهٔ کامل دیتابیس → «دریافت لیست دیتابیس‌ها» → انتخاب دیتابیس → خواندن تنظیمات
  از دیتابیس → «بررسی سلامت اتصال» → از این پس هر ویزیتور با نام کاربری و کلمهٔ عبور خودش وارد می‌شود.
* کد نمونهٔ Kotlin این دو مرحله در [ANDROID_INTEGRATION.md](../ANDROID_INTEGRATION.md) آمده است.

### چیزهایی که باید یک‌بار روی ویندوز تست شود

- [ ] تیک پاک‌سازی IIS: پشتیبان ساخته می‌شود، سایت‌های قبلی حذف و سایت `Vizitor` روی ۹۵۹۵ ساخته می‌شود.

- [ ] گزارش نهایی: خط «سلامت اتصال: تایید شد ✓».

## ۱۶) آیا برای اتصال اندروید به SQL Server، IIS لازم است؟  **خیر**

| کار | به IIS نیاز دارد؟ | چه چیزی لازم است |
|---|---|---|
| **اتصال مستقیم برنامهٔ اندروید به دیتابیس (۱۴۳۳)** — خواندن جدول‌ها، قیمت‌ها، ثبت و ارسال پیش‌فاکتور | ❌ **نه** | فقط SQL Server روی همان سرور + باز بودن پورت **۱۴۳۳** برای شبکهٔ محلی + کاربر دیتابیس |
| ورود ویزیتور با نام کاربری/کلمهٔ عبور خودش | ❌ نه | همان اتصال مستقیم (`dbo.sys_users`) |
| پنل وب مدیریت، `/api/health`، فعال‌سازی سامانه، نمایش وضعیت | ✅ بله (یا خود API روی ۹۵۹۵) | یا IIS روی ۹۵۹۵، یا بدون IIS: خود API روی ۹۵۹۵ |
| کد QR / کارت اتصال | ❌ نه | فایل‌های ساخته‌شده در `C:\Vizitor\setup` |

**در نسخهٔ ۱.۱ چه چیزی تغییر کرد:**
* تیک **IIS** در صفحهٔ اول ویزارد **پیش‌فرض خاموش** است و متنش هم گویا شده:
  «اجرای پنل وب از طریق IIS (اختیاری — برای اتصال مستقیم اندروید لازم نیست)».
* تیک **پاک‌سازی کامل IIS** هم فقط وقتی معنا دارد که تیک IIS روشن باشد.
* نوار وضعیت ویزارد حالا می‌گوید: «IIS: نصب است (برای اتصال مستقیم اندروید لازم نیست)» و
  «اتصال اندروید: مستقیم به SQL Server روی پورت ۱‍۴۳۳ — بدون نیاز به IIS یا API».
* نصب‌کنندهٔ خط فرمان (`install.ps1`) هم اگر بدون پارامتر اجرا شود، پیش‌فرض IIS را **خیر** می‌گیرد.

**نتیجهٔ عملی:** برای کار ویزیتورها فقط این‌ها لازم است:
1. سرویس SQL Server در حال اجرا باشد و پورت ۱۴۳۳ در شبکهٔ محلی باز باشد (نصب‌کننده این قاعده را می‌سازد).
2. کاربر دیتابیس با گرنت‌های لازم (`vizitor_android` که نصب‌کننده می‌سازد، یا کاربر خود برنامهٔ حسابداری).
3. برنامهٔ اندروید فقط یک‌بار نشانی سرور (آی‌پی داخلی یا ثابت) + کاربر/رمز دیتابیس را بگیرد، لیست دیتابیس‌ها را بگیرد و دیتابیس حسابداری را انتخاب کند.

> اگر IIS نصب نیست یا نمی‌خواهید دست بخورد: تیک آن را نزنید. پنل وب در همان حالت بدون IIS هم
> روی `http://<آی‌پی-سرور>:9595` بالا می‌آید (خودِ API)، پس هیچ قابلیتی از دست نمی‌رود.
